# **PHOENIX PORTAL STYLE**
### *Canonical Style Specification for the Phoenix Entry Portal*
### *EF–CO Canonical Document*

---

## **1. Purpose**

This document defines the **visual style**, **layout rules**, and **accessibility guidelines** for the Phoenix Entry Portal.

It ensures:

- consistent presentation  
- readable mathematical content  
- clear epoch navigation  
- compatibility with light/dark mode  
- long-term stability for public access  

This is the official style specification for the Phoenix portal.

---

## **2. Light/Dark Mode**

The Phoenix Portal inherits GitHub Pages’ automatic theme switching.

### **2.1 Requirements**

- All text must remain readable in both modes.  
- No custom colors may conflict with GitHub’s theme.  
- Mathematical expressions must remain visible under both themes.  
- Links must remain distinguishable in both themes.

### **2.2 Behaviour**

GitHub Pages automatically applies:

- light mode when the visitor’s system is light  
- dark mode when the visitor’s system is dark  

No additional configuration is required.

---

## **3. Typography**

Phoenix Portal uses GitHub’s default typefaces.

### **3.1 Requirements**

- Headings must use Markdown `#`, `##`, `###`  
- Mathematical expressions must use LaTeX blocks  
- Lists must be clean and minimal  
- No inline HTML styling  

### **3.2 Mathematical Display**

synthetic expression


for block math.

---

## **4. Layout**

Phoenix Portal layout must remain:

- simple  
- readable  
- epoch-structured  
- consistent across documents  

### **4.1 Document Layout**

Each document must begin with:

- Title  
- Subtitle  
- EF–CO Canonical Document marker  

### **4.2 Spacing**

- One blank line between sections  
- No trailing whitespace  
- No excessive indentation  

---

## **5. Accessibility**

Phoenix Portal must remain accessible to:

- mathematicians  
- engineers  
- researchers  
- synthetic domain analysts  

### **5.1 Requirements**

- All links must be descriptive  
- All headings must be meaningful  
- All math must be readable  
- All epochs must be clearly separated  

---

## **6. Visual Coherence**

Phoenix Portal must maintain:

- consistent heading hierarchy  
- consistent epoch grouping  
- consistent document ordering  
- consistent link formatting  

This ensures Phoenix remains readable for generations.
