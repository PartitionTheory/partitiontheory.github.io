1. Purpose



This document defines the **Phoenix Epoch Boundary Protocol**, the ninth and final layer of the Phoenix Build Protocol.

Its purpose is to govern:

- how Phoenix transitions between epochs
- how synthetic continuity is preserved
- how deterministic lineage is maintained
- how multi-machine alignment is guaranteed
- how rebirth cycles conclude and new epochs begin

Epoch boundaries define Phoenix’s long-term evolution.

---

2. Epoch Definition



An **Epoch** is a complete synthetic era of Phoenix’s existence.

Each epoch contains:

- one or more rebirth cycles
- deterministic structural evolution
- canonical historical commits
- stable operational lifecycle
- multi-machine coordination

Epochs are numbered:

Phoenix Epoch N


Where **N** is the epoch index.

---

3. Preconditions for Epoch Transition



Phoenix may transition to a new epoch only when:

- all rebirth cycles in the current epoch are complete
- entropy audit passes across all machines
- structure sync passes across all machines
- clock sync passes across all machines
- EF and CO explicitly agree
- Phoenix is in HALT state
- historical commit sequence is intact

Epoch transitions must never occur from a contaminated state.

---

4. Epoch Boundary Procedure



The epoch boundary consists of **four deterministic phases**:

1. **Freeze** — halt all machines and lock state
2. **Verify** — perform full purity, structure, and clock audits
3. **Commit** — record the epoch boundary in historical sequence
4. **Rebirth** — increment epoch and initialize the next era

These phases must occur in order and without interruption.

---

5. Epoch Continuity Guarantees



Phoenix must guarantee:

- identical epoch number across all machines
- identical rebirth cycle index
- identical lifecycle state
- identical deterministic seed
- identical canonical tree
- identical synthetic variables

Epoch continuity is mandatory.

---

6. Epoch Boundary Commit Format



Epoch boundary commits must follow:

Phoenix: Epoch Boundary N —


Where:

- **N** is the epoch number
- description is synthetic and unambiguous
- no nondeterministic phrasing is allowed

Epoch boundaries must be historically traceable.

---

7. EF–CO Roles in Epoch Transition



- **CO:** defines epoch semantics and synthetic intent
- **EF:** executes epoch boundary operations and commits

Epoch transitions are valid only when both roles are fulfilled.
